# Умный поиск по каталогу

Тестовое задание, этап 2 (ГК «Проф-Пресс»). Гибридный поиск по каталогу
(Fuzzy-коррекция → BM25 + семантический поиск, объединение через RRF),
FastAPI-эндпоинт и `evaluate.py` для измерения качества.

Архитектура и ход решения (включая отклонённые варианты) — см.
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md). Отчёт по заданию — см.
[`docs/REPORT.md`](docs/REPORT.md).

## Запуск (три команды)

Требуется только Docker + Docker Compose. Работает на обычном ноутбуке без
видеокарты — модель эмбеддингов раздаётся CPU-образом.

```bash
# 1. Поднять сервисы (первый запуск: скачивание весов модели, ~2-4 минуты)
docker compose up -d --build

# 2. Прогнать оценку качества (пишет data/eval_result_<timestamp>.csv)
docker compose run --rm app python evaluate.py

# 3. Запросить поиск
curl "http://localhost:8000/search?q=свечки+на+торт+для+мальчика&k=3"
```

Остановить: `docker compose down` (добавить `-v`, чтобы также удалить кэш
весов модели в volume `model-cache`).

## Модели, данные, переменные окружения

- **Эмбеддинги**: `intfloat/multilingual-e5-base`, self-hosted через
  `ghcr.io/huggingface/text-embeddings-inference:cpu-1.8.1` (отдельный сервис
  `embeddings` в `docker-compose.yml`). Веса скачиваются автоматически при
  первом старте с HuggingFace Hub, кешируются в именованном volume
  `model-cache` — повторные пересборки образа приложения их не трогают.
  Никакого API-ключа не нужно, ничего не отправляется вовне (приватность
  каталожных данных — исходное требование, см. `docs/ARCHITECTURE.md` п.2).
- **Лемматизация**: `pymorphy3` (русский язык, оффлайн-словарь).
- **Fuzzy-коррекция**: `rapidfuzz` (Левенштейн-подобная метрика).
- Переменная окружения `EMBEDDINGS_URL` — адрес сервиса эмбеддингов
  (по умолчанию `http://embeddings:80` в Docker-сети, `http://localhost:8080`
  при ручном запуске вне compose). API-ключей не требуется.

## API

`GET /search?q=<запрос>&k=<число>` — до `k` результатов (по умолчанию 3),
каждый: `article` (Артикул), `name` (Наименование), `category` (Категория),
`price` (Цена), `score` (оценка релевантности). Артикул — единственный ключ,
по которому результат связывается с 1С, присутствует в каждом результате.

`GET /health` — готовность пайплайна (каталог загружен, эмбеддинги получены).

## Данные и что не входит в репозиторий

`data/products.csv` (211 позиций) и `data/queries.csv` (30 запросов) —
входные данные задания, коммитятся как есть, `queries.csv` не редактировался.

Не коммитятся (генерируются автоматически при запуске, см. `.gitignore`):
`data/enrichment.csv` (детерминированный вывод `app/build_enrichment.py`,
пересобирается из текущего `products.csv` при каждом старте) и
`data/eval_result_*.csv` (по-запросные результаты каждого прогона
`evaluate.py`, с таймстемпом в имени).
